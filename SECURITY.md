# Security Policy

## Supported Versions

The following versions of this project are currently supported with security updates:

| Version        | Status               |
| -------------- | -------------------- |
| Latest release | Supported            |
| Older versions | Not supported       |

If you are using an unsupported version, you should upgrade to the latest release to receive security fixes.

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it through one of the following channels:

- **Preferred:** Email the maintainers at `security@example.com` with the details of the issue.
- **Alternative:** Open a private security advisory or confidential issue if supported by the hosting platform.

When reporting a vulnerability, please include:

- A description of the issue and its potential impact.
- Steps to reproduce, if possible.
- Any relevant logs, proofs of concept, or configuration details.

Please do **not** disclose the vulnerability publicly before we have had a reasonable opportunity to investigate and prepare a fix.

## Response Expectations

We aim to:

- Acknowledge vulnerability reports within **5 business days**.
- Provide an initial assessment or request for more information within **10 business days** of acknowledgment.
- Work on a fix and release security updates as quickly as practical, depending on the complexity and impact of the issue.

If you do not receive a response within the time frames above, you may send a follow-up using the same communication channel.

## Disclosure Policy

We follow a coordinated disclosure approach:

- After confirming the vulnerability and preparing a fix or mitigation, we will publish a new release and update the project documentation or release notes as appropriate.
- We will credit reporters who wish to be recognized, provided that doing so does not create additional security risks.
- We request that you wait to publicly disclose details of the vulnerability until a fix has been released or **30 days** have passed since our acknowledgment, whichever comes first, unless we mutually agree on a different timeline.

If the project is no longer actively maintained, we will make a reasonable effort to communicate that status clearly in the repository so that users can make informed decisions about their use of the software.
